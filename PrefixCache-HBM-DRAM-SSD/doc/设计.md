# PrefixCache HBM / DRAM / SSD 评测

## 目的

在昇腾 910C 单机单卡、vLLM/vLLM-Ascend 0.23.0 和 Mooncake 环境中，对完全相同的
16K P1 请求比较四个阶段的 TTFT：

- `R1-warmup`：HBM 和外部 Prefix Cache 均未命中的冷请求；
- `R2-hbm-cache`：vLLM 本地 HBM Prefix Cache 命中；
- `R3-dram-cache`：本地 HBM 未命中，从 Mooncake DRAM 恢复；
- `R4-ssd-cache`：本地 HBM 和 Mooncake DRAM 均未命中，从 Mooncake SSD 恢复。

正式入口只有两个：

```bash
bash StartUp.sh
bash Run-all
```

`StartUp.sh` 一次性开启 DRAM + SSD 分层能力，执行 R1～R4 的过程中不切换 SSD
开关。`Run-all` 负责移动数据、逐阶段验证来源并生成同一个结果文件。

## 为什么来源判定可靠

不能仅靠 vLLM 的 `external_prefix_cache` 命中判断 DRAM/SSD，因为该指标只表示命中
外部 Prefix Cache，不包含 Mooncake 存储层级。

本测试联合使用四类独立证据：

1. P1 身份：捕获实际 prompt，校验 token 数、全文 SHA256、token SHA256 和首个
   128-token block SHA256；R1～R4 必须完全一致。
2. vLLM 路径：使用阶段前后的 local/external token counter 增量，区分 HBM 与外部
   Prefix Cache，并排除重算。
3. Mooncake tier：使用 master 的 DRAM/SSD hit、hit bytes 和 valid get counter 增量，
   证明每一次有效 Mooncake lookup 具体由 MEMORY 还是 LOCAL_DISK 提供。
4. 物理设备读：R4 前后读取 `/sys/class/block/<kname>/stat` 的 read sectors，要求
   块设备读取字节增量不小于 Mooncake 报告的 SSD hit bytes；同时启动时启用
   io_uring/O_DIRECT 路径，防止 Linux
   文件页缓存让 `file_cache` 命中看起来像真实 SSD I/O。

阶段硬条件如下：

| 阶段 | vLLM 条件 | Mooncake tier 条件 | 结论 |
|---|---|---|---|
| R1 | local、external 均 ≤ 5% | 无读取层级要求；SSD 副本必须完成 | MISS |
| R2 | local 覆盖全部可缓存 block | 不参与来源判定 | HBM |
| R3 | local ≤ 5%，external 覆盖全部可缓存 block | `valid_gets > 0`，全部 valid get 都计入 DRAM，SSD hit/bytes 为 0 | DRAM |
| R4 | local ≤ 5%，external 覆盖全部可缓存 block | `valid_gets > 0`，全部 valid get 都计入 SSD，DRAM hit/bytes 为 0，块设备 read bytes 增量 ≥ SSD hit bytes | SSD |

默认 16K 输入、128 block 时，“全部可缓存 block”的最低 token hit rate 为
`(16384-128)/16384 = 99.21875%`，比通用的 95% 下限更严格；最后一个 block 不作为
可复用 Prefix Cache。修改输入长度或 block size 后脚本会自动重算该门槛。

使用的 Mooncake master 指标包括：

```text
mem_cache_hit_nums_
file_cache_hit_nums_
mem_cache_hit_bytes_total
file_cache_hit_bytes_total
mem_cache_nums_
file_cache_nums_
valid_get_nums_
master_evicted_key_count_mem
```

启动或测试时缺少任一指标、SSD 块设备统计不可读，或 R4 没有观察到物理设备读取，
都会直接失败。若 R4 实际混入 DRAM 命中，来源会打印为
`DRAM` 或 `MISS_OR_MIXED`，该 batch 的 R4 被标为无效并从 Summary 排除；严格模式
默认返回退出码 2。

这些指标是 master 的全局计数器，正式评测期间不能向同一套 vLLM/Mooncake 实例发送
其他业务请求，否则其他流量会污染阶段增量。

## 每种并发的执行流程

```text
Phase A：对每个 batch 依次执行
  清 HBM，保留 Mooncake
    -> R1：发送全新 P1，验证冷请求
    -> 等待 Mooncake Keys 稳定及 eager SSD replicas 完成
    -> R2：重放 P1，验证 local HBM 命中
    -> 清 HBM
    -> R3：重放 P1，验证所有 Mooncake valid get 来自 DRAM

Phase B：本并发的所有 R3 完成后
  等待 R3 read lease 过期
    -> 记录压力前全部 DRAM 对象数
    -> 发送独立压力请求，直到 eviction 数覆盖压力前全部 DRAM 对象
    -> 对每个 batch：清 HBM -> R4 -> 验证全部 valid get 来自 SSD
```

Mooncake 以 eager 模式运行：R1 写入完成后，P1 同时拥有 MEMORY 与 LOCAL_DISK 副本。
R3 的读取选择 MEMORY；随后压力请求触发 DRAM eviction，SSD 副本继续保留。R4 集中
到一次全量 DRAM eviction 后执行，避免每个 batch 都重复填满数百 GB DRAM。
R3 读取会给对象授予约 11 秒 lease，因此压力前默认等待 12 秒；否则 P1 仍受 lease
保护，eviction 可能只淘汰其他对象，导致 R4 继续命中 DRAM。

压力目标覆盖压力开始前的整个 DRAM working set，而不是只覆盖 P1 数量；R4
阶段的 tier hit/bytes 增量才是最终来源证据。因此即使淘汰顺序与预期不同，脚本也只会
排除结果，不会把 DRAM 误报成 SSD。

## P1 请求设计

默认四种并发，每种并发执行 5 个 batch：

| 并发 | 每批请求 | batch 数 | 唯一 P1 请求数 | 四阶段总推理数 |
|---|---:|---:|---:|---:|
| C1 | 1 | 5 | 5 | 20 |
| C5 | 5 | 5 | 25 | 100 |
| C10 | 10 | 5 | 50 | 200 |
| C100 | 100 | 5 | 500 | 2000 |
| 合计 |  |  | 580 | 2320 |

同一 batch 内、不同 batch、不同并发之间的 P1 都必须唯一；同一个 `prompt_id` 在
R1～R4 中必须完全相同。每条请求的第一个 128-token block 也必须唯一。

## 启动配置

`StartUp.sh` 会：

- 为本次会话创建新的空 SSD 子目录，避免旧数据污染 R1；
- 使用 `findmnt` 和 `lsblk` 验证路径位于本地非旋转块设备，拒绝 tmpfs、非块设备和
  旋转盘；容器 overlay 仅在显式指定后端块设备并通过 O_DIRECT 映射探针后放行；
- 在 `mooncake.json` 中设置 `enable_ssd_offload=true` 和 `ssd_offload_path`；
- 使用 `--enable_offload=true --offload_on_evict=false` 启动 master；
- 使用 `--promotion_on_hit=false`，避免 R4 首次 SSD 命中后自动提升到 DRAM；
- 设置 `MOONCAKE_OFFLOAD_USE_URING=1`，启用 Mooncake 的直接 I/O 读取路径；
- 记录 SSD 的 kernel block name，供 `Run-all` 对 R4 的设备 read sectors 做增量校验；
- 检查可靠性判定所需的全部 master 指标。

默认 SSD 根目录为 `/mnt/mooncake-ssd-offload`。可在启动前覆盖：

```bash
MOONCAKE_SSD_ROOT=/mnt/nvme/mooncake \
MOONCAKE_SEGMENT_GB=256 \
MOONCAKE_SSD_BUFFER_GB=8 \
MOONCAKE_SSD_QUOTA_GB=3072 \
bash StartUp.sh
```

当前评测容器默认使用 `/mnt/mooncake-ssd-offload`，并将已确认的
`/dev/nvme3n1p1` 作为 overlay 后端，因此可以直接启动：

```bash
bash StartUp.sh
```

迁移到其他容器时，可以用 `MOONCAKE_SSD_ROOT` 和 `MOONCAKE_SSD_BLOCK_DEVICE` 覆盖
这两个默认值。

脚本会先对会话目录执行 256MiB O_DIRECT 写入和读取，并要求指定块设备的 write/read
sectors 分别至少增加 256MiB。探针失败时仍拒绝启动，不能仅凭环境变量绕过校验。

SSD 路径必须是已经挂载的真实 SSD 文件系统。每次启动会先清理由旧版本遗留的
`session-*` 缓存目录，再创建新的 `session-时间-PID` 子目录。

`Run-all` 默认在成功、失败或中断退出时通知 `StartUp.sh` 停止 vLLM/Mooncake，并删除
本次 SSD 会话目录；单独停止 vLLM 或终止 `StartUp.sh` 也会触发同一清理。这里只删除
SSD KV Cache，`vb-result/` 下的 JSON、Excel、manifest 等评测结果会保留。需要在失败后
保留运行现场调试时，可显式设置：

```bash
VB_CLEANUP_AFTER_RUN=0 bash Run-all
```

Mooncake SSD offload 需要安装版本支持 `enable_ssd_offload`、`ssd_offload_path` 以及
上述 tier metrics。能力不足时启动或评测会明确失败，不会降级为不可靠判定。

## 执行参数

```bash
VB_BATCHES=5
VB_INPUT_LEN=16384
VB_BLOCK_SIZE=128
VB_BASE_SEED=314159
VB_MIN_HIT_RATE=0.95
VB_MAX_MISS_RATE=0.05
VB_STORE_STABLE_SECONDS=2
VB_STORE_TIMEOUT_SECONDS=300
VB_SSD_PRESSURE_CONCURRENCY=10
VB_SSD_PRESSURE_MAX_ROUNDS=200
VB_SSD_PRESSURE_TIMEOUT_SECONDS=1800
VB_SSD_EVICTION_LEASE_WAIT_SECONDS=12
VB_CLEANUP_AFTER_RUN=1
VB_STRICT=1
VB_RUN_DIR=/mnt/data/my-run
VB_MOONCAKE_METRICS_URL=http://127.0.0.1:9003/metrics/summary
VB_MOONCAKE_PROMETHEUS_URL=http://127.0.0.1:9003/metrics

```

若压力阶段达到轮数或时间上限仍没有足够的 DRAM eviction，脚本立即失败。可根据实际
DRAM 容量调整压力并发、轮数与超时，但不能关闭 R4 tier 校验。

## 输出

默认结果目录为北京时间命名的 `vb-result/YYYY-MM-DD HH-MM-SS/`，包括：

- `vb-result.xlsx`；
- `C1-result.json`、`C5-result.json`、`C10-result.json`、`C100-result.json`；
- `json/C*/R*/` 原始 vLLM 详细结果；
- `json/C*/ssd-pressure/` SSD 下沉压力的原始结果；
- `p1-manifest.json` 和 `p1-prompts.jsonl`；
- `session.json`。

Excel Sheet 顺序为：

1. `Summary`；
2. `R1-warmup`；
3. `R2-hbm-cache`；
4. `R3-dram-cache`；
5. `R4-ssd-cache`；
6. `validation`；
7. `P1-manifest`。

Summary 同时提供 R3/R2、R4/R2 和 R4/R3 的绝对及百分比劣化。`validation` 保存每个
stage/batch 的 local/external 命中率、Mooncake valid gets、DRAM/SSD hits、bytes、
SSD block-device read bytes、
最终来源、有效性和判定依据。执行过程中也会打印 `KV来源=HBM/DRAM/SSD` 及简要依据。

## 容量注意事项

Mooncake DRAM 必须至少能容纳当前一个 P1 batch，否则 R3 无法形成纯 DRAM 基线。
Qwen3-8B BF16 KV 按约 2.25GB/条 16K 请求估算，C100 单批约 225GB，因此默认使用
256GB DRAM 段；主机还需为 vLLM、SSD buffer、Mooncake 元数据和操作系统预留内存。

SSD quota 必须能容纳 P1 和压力请求产生的副本。默认磁盘 eviction policy 为 `none`：
空间不足时宁可失败，也不允许静默删除 P1 后把 R4 变成重算。
完整 C1/C5/C10/C100 按当前 Qwen3-8B 估算建议至少准备约 3TB 可用 SSD 空间；
`StartUp.sh` 默认 quota 为 3072GB，并在启动前校验文件系统可用空间。3072GB 是容量
上限和启动前的可用空间门槛，不是需要永久保留的评测结果；本次运行退出清理后，SSD
KV Cache 文件会被删除并归还空间。
